## 1. 개발 목표

기존 0~5성 수배 시스템에서 별 단계가 올라갈수록 단순히 일반·정예 경비 숫자만 늘어나는 구조를 개선한다.

4성부터 E-03 중장갑 경비를 투입하고, 5성에서는 E-04 감시 드론을 추가해 별 단계마다 플레이어가 다른 방식으로 도주하고 대응하게 만든다.

24일차에서 구축한 지상·지하 추격 구조와 연결해 E-03은 실제 계단을 이용해 지하로 따라오고, E-04는 지하로 진입하지 않고 지상 입구 주변을 감시하도록 구성한다.

---
## 2. 수배 대응 병력 종류 확장

기존 E-01·E-02 구분을 다음 네 종류로 확장한다.

```text
MapWantedUnitKind
├─ Regular             E-01
├─ Elite               E-02
├─ Heavy               E-03
└─ SurveillanceDrone   E-04
```

기존 E-01·E-02 초기화 방식은 유지하면서 E-03을 같은 `MapWantedGuardAgent` 기반 지상 경비로 확장한다.

E-04는 공중 이동 특성이 달라 별도의 `Map25SurveillanceDrone`으로 관리한다.

## 4. E-03 중장갑 경비

E-03은 빠르게 쫓아오는 적보다 도주 길목을 압박하는 느린 방어형 병력으로 구현한다.

기본 능력치는 다음과 같다.

| 항목 | 값 |
|---|---:|
| 체력 | 180 |
| 자세 | 160 |
| 기본 공격 | 30 |
| 강공격 | 48 |
| 추격 속도 | 3.8m/s |
| 시야 | 16m / 85° |
| 청각 | 14m |
| 암살 | 불가능 |

E-03은 기존 `MapWantedGuardAgent`를 재사용해 다음 기능을 그대로 이용한다.

- 플레이어 직접 추격
- 5초 위치 공유 추적
- 마지막 확인 위치 분산 수색
- Day23 정체 복구
- Day24 지상·지하 계단 추격
- 지하 승강장·서비스 통로 수색

E-03의 방향 전환과 수색 속도는 E-01·E-02보다 느리게 설정한다.

---
## 5. E-03 배치 방식

4성부터 E-03을 플레이어 바로 옆에 생성하지 않고 기존 보행 그래프의 노드 중 도주 예상 방향에 가까운 위치를 찾는다.

기본 배치 조건은 다음과 같다.

- 플레이어 또는 지하철 입구 기준 약 42~92m
- 다른 활성 경비와 약 7m 이상 분리
- 경비별로 서로 다른 각도의 차단 방향 선택
- 지하 플레이어 추적 중에는 지하철 지상 입구 주변 길목 우선

이를 통해 E-01·E-02가 뒤에서 추격하고 E-03이 앞쪽 길목을 압박하는 구성을 만든다.

## 6. E-03 내려찍기·충격파

기존 검 공격 외에 E-03 전용 압박 공격 `Map25HeavyPressure`를 추가한다.

기본 동작은 다음과 같다.

```text
플레이어 거리 2.7~4.6m
↓
0.85초 내려찍기 예고
↓
충격파 판정
↓
체력 피해 48
자세 피해 36
↓
6.5초 재사용 대기
```

충격파는 벽 너머에 있는 플레이어에게 피해를 주지 않도록 경로 차단 검사를 사용한다.

자세 붕괴나 마비 상태에서는 충격파 준비를 취소한다.

## 7. E-04 감시 드론

5성에서만 E-04 감시 드론을 최대 두 대 투입한다.

기본 능력치는 다음과 같다.

| 항목 | 값 |
|---|---:|
| 내구도 | 60 |
| 비행 속도 | 4.5m/s |
| 시야 | 22m / 110° |
| 정보 공유 거리 | 25m |
| 직접 공격 | 없음 |
| 암살 | 불가능 |

드론은 플레이어 주변을 원형으로 이동하며 플레이어 방향으로 감시 렌즈를 회전한다.

플레이어를 직접 발견하고 25m 이내라면 기존 `MapWantedSystem.BroadcastDetection`을 재사용해 전체 수배 경비에 정확한 위치를 공유한다.

## 8. 지하에서의 E-04 행동

E-04는 지하 Terrain으로 내려가지 않는다.

플레이어가 지하에 있을 때는 Day24의 `Map24LayerNavigation.SurfaceAnchor`를 사용해 지하철 지상 입구를 감시 중심으로 전환한다.

```text
플레이어 지상
→ 플레이어 주변 공중 순찰

플레이어 지하
→ 지하철 지상 입구 주변 감시
```

따라서 지하는 드론 시야에서 벗어날 수 있는 공간으로 유지하면서, 다시 지상으로 나오는 시점에는 감시 압박이 존재하도록 구성한다.

## 9. E-03·E-04 자동 생성과 풀링

`Map25ResponseDirector`는 런타임에 자동 생성된다.

별도 프리팹이나 씬 오브젝트를 수동으로 배치하지 않아도 다음 풀을 준비한다.

```text
WantedSpecialResponsePool
├─ E-03 중장갑 경비 × 3
└─ E-04 감시 드론 × 2
```

E-03과 E-04의 외형은 현재 단계에서 Unity Primitive를 이용해 런타임에 생성한다.

E-03은 중장갑 체형과 주황 경고등, E-04는 공중 감시 코어와 청록 추진부·적색 감시 렌즈로 구분한다.

---
## 10. 수배 단계 하락과 철수

수배 단계가 내려가면 현재 단계에 필요 없는 특수 병력을 철수시킨다.

```text
★★★★★
E-01 + E-02 + E-03 + E-04

↓ 4성

E-04 철수

↓ 3성

E-03 철수

↓ 0성

기존 수배 경비 철수
```

파괴되거나 사망한 특수 병력은 일정 시간 유지한 뒤 풀로 복귀한다.

## 12. 기존 지상·지하 이동 연동 수정

`Map24GuardLayerAgent`가 E-03의 병력 종류를 인식하도록 수정한다.

지하 수색에서도 E-03은 다른 경비보다 느리게 이동하고 수색 지점에서 더 오래 머문다.

## 13. Project K Day 메뉴 정리

개발 과정에서 Unity 상단 `Project K` 메뉴에 누적된 Day 개발용 메뉴가 많아져 메뉴를 정리한다.

`Assets/_Project/Editor` 아래 스크립트에서 다음 형태의 등록을 제거한다.

```text
MenuItem("Project K/Day ...")
```

실제 Day1~Day25 런타임 기능과 Editor 클래스 본체는 유지하고 메뉴 등록 속성만 제거한다.

따라서 기존 게임 기능은 유지하면서 Unity 상단 `Project K` 메뉴에서 Day 개발용 메뉴만 사라진다.

정리 과정에 사용한 `ProjectKDayMenuCleanup.cs`는 일회용 파일이므로 최종 25일차 amend 전에 `.cs`와 `.meta`를 저장소에서 제거한다.
